API Design Rules
Use plural resource names (/doctors, /appointments, /reports).
Use HTTP verbs correctly (GET, POST, PUT/PATCH, DELETE).
Keep URLs noun-based; actions appear only where appropriate (e.g., /check-in, /refresh-token).
Apply pagination, filtering, sorting, and search consistently to collection endpoints.
Protect private endpoints with JWT authentication.
Return standardized success and error envelopes.

Architect Recommendation

This should be considered the official API Contract v1.0 for DermAssist AI. It is intentionally scoped to support the current product vision and Phase 4–5 implementation. Future enterprise capabilities (RBAC management APIs, WebSockets, telemedicine, wearable integrations, streaming AI, etc.) should be introduced in later API versions (v2.x/v3.x) rather than expanding this contract, keeping v1.0 stable for frontend integration and production deployment.
